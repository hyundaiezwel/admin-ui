> **DS1 당시 측정, --ez-* 토큰 서술은 DS3에 해당 없음.**
> 어드민 목업 저장소(`ez-admin-design-system`, 폐기)의 `docs/spike-report.md`를 옮겼다. DS3가 PrimeVue 4.5를
> 쓰는 근거 기록이다. 스파이크 소스(`spike/`·`shared/measure.ts`)는 저장소와 함께 사라지므로 재현 절은 뺐다.
> 대비 수치는 DS1 토큰 기준이고, DS3 대비는 `npm run check:contrast`가 정본이다.

# UI 라이브러리 실측 보고 — Nuxt UI 4.11 vs PrimeVue 4.5.5

측정일 2026-09-19 / 소스 `spike/nuxt-ui`, `spike/primevue`

두 스파이크는 **같은 화면(문의 답변 관리), 같은 문구, 같은 시드 고정 데이터**를 쓴다.
다른 것은 컴포넌트 출처뿐이라 결과 차이를 라이브러리로 돌릴 수 있다.

한 앱에 둘을 섞지 않고 워크스페이스로 갈라 세운 이유 — Tailwind preflight가 전역이라
같은 문서에 두면 PrimeVue 화면까지 먹어 측정이 오염된다.

계측은 `shared/measure.ts`가 한다. **토큰 정의를 읽어 계산하지 않고 `getComputedStyle`로
렌더된 픽셀 색을 잰다.** 라이브러리가 그 토큰을 실제로 쓰는지가 질문이기 때문이다.

| 항목 | Nuxt UI | PrimeVue |

## 4. Tabulator 공존 — 충돌 없음

그리드 요소 7곳의 computed style 지문을 두 앱에서 떠 비교했다 — **완전히 동일**하다.
Tailwind preflight는 `.ez-grid` 하위를 건드리지 않았다.

다만 그리드 자체에서 두 가지를 배웠다.

1. **Tabulator 기본 CSS는 반드시 넣어야 한다.** 색만 우리가 칠하려고 테마를 빼 봤더니
   표가 세로로 무너졌다. 기본 CSS에 레이아웃 구조(가상 렌더 컨테이너 position, 셀 width 계산)가
   들어 있고 구조만 뽑은 배포본은 없다. 가장 얇은 `tabulator_simple`을 깔고 위를 토큰으로 덮는다.
2. **`selectableRange`를 켜면 첫 컬럼이 '행 헤더' 거터로 바뀐다.** 우리 체크박스 컬럼이 그 자리라
   모듈이 자기 회색(`#d6d6d6`)을 칠한다. 토큰으로 되돌리는 규칙이 필요하다.

## 5. 우리 토큰 결함 3건 — 라이브러리 선택과 무관하게 고쳐야 한다

이번 측정에서 양쪽 공통으로 걸린 실패는 전부 `@ezwel/ui` v1.0.0 쪽이다.

### (1) `--ez-text-muted`가 캔버스 위에서 미달 — 3.90:1

토큰 문서는 "step 50 = 4.5:1"이라고 적었다. 그 약속은 **흰 배경 전제**였는데,
페이지 배경(`--ez-surface-canvas` = gray-10) 위에 직접 놓인 보조 텍스트는 3.90:1이다.

카드 안(흰 면)에서는 통과하고 페이지 배경 위에서만 실패한다 — 그래서 눈으로는 안 잡힌다.

**고칠 방향** — 둘 중 하나.
- step 번호의 약속을 "흰 배경 기준"이 아니라 **"`--ez-surface-canvas` 기준"**으로 재정의하고
  스케일을 다시 생성한다(가장 어두운 면을 기준으로 잡으면 모든 면에서 안전하다).
- 또는 캔버스 위 텍스트 전용 토큰(`--ez-text-muted-on-canvas`)을 둔다. 이름이 늘어나는 쪽이라
  선호하지 않는다.

### (2) `--ez-color-gray-50`이 4.48:1 — 약속에 0.02 모자란다

목표 상대휘도로 생성했지만 8비트 양자화에서 반올림이 아래로 떨어졌다. 한 단계 어둡게
재생성해야 한다. 그리드 헤더 실패가 이것이다.

### (3) `--ez-color-danger-50` 위 흰 글자가 4.4999:1 — 경계

표시는 4.50이지만 판정은 실패다. danger 램프도 같이 재생성 대상이다.

> **해소됨 — `@ezwel/ui` v1.1.0.** 목표값을 올리는 것으로는 부족했고 **기준면 자체를
> 흰색에서 캔버스로 내렸다.** 가장 어두운 면에서 통과하면 밝은 면에서는 자동으로 통과하고,
> 색 면 위 흰 글자까지 한 기준으로 묶인다.
>
> 검사 스크립트(`check-contrast.mjs`)를 붙이자 의미 토큰 조합 **278쌍 중 42건**이 미달이었다 —
> 브라우저로 잡은 4건은 그중 눈에 띈 일부였을 뿐이다. 지금은 라이트·다크·고대비 전 조합에서
> 0건이고 `npm run verify`에 물려 있다.
>
> 사내 표준 주색 `#009782`는 캔버스 기준 2.6:1이라 스케일에서 빠졌다. `--ez-brand`로
> 분리해 로고·큰 면적에만 쓴다.

## 6. 통합 중 만난 함정

측정보다 이쪽이 실무에 더 쓸모 있다. **전부 오류 없이 조용히 틀리는 종류**다.

### Nuxt UI

1. **테마계가 어긋난다.** Nuxt UI가 OS 다크 설정을 보고 `html.dark`를 스스로 달았는데
   우리 토큰은 `data-theme="light"`를 보고 있었다. 라이트 토큰 위에 다크 컴포넌트 스타일이
   얹혀 **CTA 대비가 1.98:1까지 떨어졌고 콘솔에는 아무것도 안 나왔다.**
   `data-theme`만 감시하는 브리지로는 부족하다 — 라이브러리가 나중에 다시 붙이므로
   `class`까지 감시해야 한다.
2. **CSS 변수 덮어쓰기만으로는 부족하다.** `--ui-color-info-500`을 우리 값으로 바꿔도
   뱃지 색이 안 변한다. `bg-info/10` 같은 유틸리티는 CSS 변수가 아니라 Tailwind `@theme`
   레지스트리를 본다. 팔레트를 거기에 **하드코딩으로 복제**해야 하고,
   그 `@theme` 블록은 `@import "@nuxt/ui"` **앞**에 와야 한다(뒤에 두면 램프가 등록조차 안 된다).
3. **`--ui-primary` 별칭이 라이트에서 step 400을 집는다.** 11단 자리 대 자리로 매핑하면
   CTA 배경이 우리 step 40(3.65:1)이 되어 AA 미달이다. 별칭만 step 50으로 끌어올려 교정했다
   (램프 전체를 밀면 텍스트·테두리가 같이 어긋난다).
4. **`vue-router`가 필수다.** 라우터를 안 쓰는 앱에서도 `Link` 컴포넌트가 import해 빌드가 깨진다.

### PrimeVue

1. **`@primevue/themes`는 4.5.4가 최신이고 `primevue`는 4.5.5다.** 버전을 맞춰 쓰면 설치가 실패한다.
2. **`@primevue/auto-import-resolver`는 v5용(5.0.1)만 배포된다.** v4와 메이저가 어긋나 못 쓴다 —
   명시적 import로 간다(스파이크 규모에서는 오히려 낫다).
3. **폼 필드 래퍼가 없다.** 라벨·도움말·오류를 묶는 `UFormField` 대응물이 v4에 없어서
   `<label>`을 앱이 소유한다. 도입하면 우리가 만들 몫이다.

### 양쪽 공통

- 의미 색 중 **`neutral` 램프만은 플러그인/프리셋 옵션으로 못 바꾼다**(타입이 고정 목록).
  CSS 변수 경로로 따로 처리해야 해서 설정이 두 갈래로 갈린다.

## 7. 남은 리스크 — PrimeVue v4 고정

이 보고서는 **v4.5.5(MIT)** 기준이다. v5는 상용 라이선스이고, 커뮤니티 자격 네 조건
(매출 100만 USD 미만 · 개발자 5명 미만 · 직원 10명 미만 · 투자 300만 USD 미만)은
웬만한 사내 조직이 만족하지 못한다 — 도입 전에 각자 확인해야 한다.

즉 **PrimeVue를 택하면 v4에 영구 고정**이다. `v4-stable` 태그로 패치는 오지만 신규 기능은
오지 않고, 언제까지 유지될지는 PrimeTek 사정이다. Nuxt UI에는 이 문제가 없다.

이 리스크를 감당할 수 없다고 판단하면 Nuxt UI로 간다. 그때 추가로 드는 일은
**뱃지 변형 재정의 + 팔레트 이중 관리 + 다크 브리지 + 밀도 슬롯 덮기** 넷이다.
