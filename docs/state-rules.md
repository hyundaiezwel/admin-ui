# 지원 사업 관리 — 상태 · 처리 규칙 (합의용 초안)

미리보기 화면(`#/sp`)이 가정한 상태 전이 규칙을 백엔드 · 기획과 맞추기 위한 문서다.
**확정이 아니다.** 표시가 `가정`인 줄은 AS-IS 분석으로 확인하지 못한 것이다.

- 코드값은 미리보기용으로 지어낸 값이다(단계별 백 단위). 실제 코드는 공통코드 테이블이 정한다.
- 규칙의 코드 정본은 화면 소스다 — 이 문서와 어긋나면 소스가 맞다. 소스를 바꾸면 이 문서도 고친다.
  - 기업 참여 상태 · 생애주기 — `src/sp/codes.ts` · `src/sp/status.ts`
  - 참여 기업 관리 허용 처리 — `src/sp/company.ts`
  - 회원 상태 허용 처리 — `src/sp/member.ts`

---

## 1. 원칙

| # | 원칙 | 왜 |
|---|---|---|
| P-1 | 상태 전이는 **도메인 서비스 한 곳**에서만 한다. 화면은 서버가 준 허용 처리 목록을 그린다 | AS-IS는 규칙이 화면 템플릿에 흩어져 행마다 버튼이 다르다 |
| P-2 | 대외 통지(LMS · E-Mail)가 따르는 처리는 **확인 팝업**을 거친다. 예외 없음 | AS-IS 접수 화면만 즉시 실행됐다 |
| P-3 | **처리 성공과 통지 성공을 따로 기록**한다. 통지 실패는 재발송 대상으로 남긴다 | AS-IS는 "처리됐으나 SMS 발송 실패" — 어느 곳인지 모른다. 통지를 브라우저가 쏜다 |
| P-4 | 일괄 처리는 **실행 전에 적격 판정**을 돌려준다(할 수 있는 곳 / 선택). 실행은 적격만 | AS-IS는 실행 뒤 "N건 중 M건 성공" 한 줄 |
| P-5 | 되돌릴 수 없는 대량 처리는 **드라이런 → 건수 입력 확인 → 감사 기록** | 일괄 참여 취소 · 전체 승인취소 |
| P-6 | 같은 처리가 경로(일반 · 에스크로)로 갈리면 **확인 팝업에 경로를 표시**한다 | AS-IS는 버튼이 같고 경로가 몰래 갈린다 |
| P-7 | 모든 처리는 감사 기록(누가 · 언제 · 조건 · 대상 · 사유)을 남긴다 | |

### 3-4. 참여회원 — `src/sp/member.ts`

| 코드 | 상태 | 할 수 있는 처리 | 결과 |
|---|---|---|---|
| M0 | 미가입 | 가입 안내 발송 | 바뀌지 않음 |
| M1 | 이용중 | 이용정지(사유 7종) | M2 |
| M2 | 이용정지 | 환불계좌 등록 · 환불요청(계좌가 있을 때) | 요청 → M3 |
| M3 | 환불요청 | 환불계좌 수정 | 바뀌지 않음 |
| M4 · M5 | 환불대상 · 환불완료 | 없음 — 배치가 옮긴다(익월 중순) | |
| M6 | 환불실패 | 환불계좌 수정 | M3 |

- 환불금액 = 잔여 포인트 − 지원기관 몫(1/4). 개인 2 : 기업 1. 지원기관 몫은 회수한다.
- 환불계좌는 **예금주 확인**을 통과해야 저장된다. 통장사본을 같이 받는다.
- 이용정지 통지 문구는 AS-IS에서 「협약파기」다 — 화면 용어(이용정지)와 통일 필요.
- `가정` 권한: 이용정지 · 일괄 이용정지는 지원담당 이상, 일괄 환불요청은 지원총괄 이상.
