# 감사에서 남은 교훈

DS1 어드민 목업의 설계 원칙 감사(2026-09-20, 10화면)에서 DS3에도 통하는 것만 추렸다.
당시 지적 목록·수치는 DS1 토큰 기준이라 옮기지 않았다.

## 1. 자동화

- **눈이 아니라 잰다.** 여백은 `getComputedStyle`과 인접 요소 경계 거리를 둘 다 재서 맞는지 본다.
  빈 상태는 실제로 0건이 되는 조건을 넣어 확인한다. "여백이 답답하다"는 감이 수치로는
  "전 화면이 사다리보다 정확히 한 단계 낮다"였다.
- **키워드 정적 검사는 오탐이 난다.** 첫 회차 6건 중 4건이 오탐이었다. 판정을 영역·화면 유형을
  아는 쪽으로 고쳐 걷어냈다 — 주 버튼 수는 모달·드로어를 다른 영역으로 세고, 빈 상태는 목록이
  있는 화면에만 요구한다. 로그인에 "결과 없음"을 요구하면 틀린 것은 화면이 아니라 규칙이다.
- **오탐이 남는 검사는 실패로 끊지 말고 보고로 남긴다.** 끊는 검사(`check:ui`·`check:contrast`)에는
  오탐이 없는 규칙만 넣는다.
- **정상만 그린 화면은 절반이다.** 목업도 지연을 넣어 로딩·오류를 실제로 지나가게 한다
  (DS3 `useMockQuery` — 검색어에 `오류`). 오류일 때 스켈레톤이 0개인지도 본다.

## 2. 감사가 놓칠 뻔한 것 — 조용히 깨지는 이름 충돌

수정 도중, 지적 목록에 없던 실제 장애가 나왔다.

| | |
|---|---|
| 원인 | 목업이 Tabulator 래퍼로 쓰던 `.ez-grid`를 디자인 시스템 새 판이 `display: grid` 프리미티브로 선언 |
| 증상 | 표 헤더가 컨테이너를 전부 먹고 본문 높이 **0px** |
| 신호 | **없음** — 콘솔 오류 0, 타입 검사·정적 감사 통과 |
| 조치 | 목업 쪽 이름을 한정(`.ez-datagrid`) + 예약 클래스 검사 추가 |

교훈 셋:

1. 타입 시스템도 린터도 CSS 클래스 충돌을 모른다. **검사를 사람에게 맡기지 않는다.**
   DS3에서는 `npm run check:ui`의 UI-30이 `src/ws/*.css`에서 예약어를 읽어 화면 쪽 재정의를 막는다.
2. 예약어 목록은 문서에 박지 않고 **배포되는 CSS에서 읽는다** — 목록이 낡지 않는다.
3. 검사기를 넣으면 **일부러 어긴 파일로 실제로 잡히는지** 한 번 확인한다.

## 3. 고치는 순서

앞의 것이 뒤의 것을 줄이는 순서로 고친다 — 정본(토큰) 하나로 묶기가 먼저, 화면 CSS 직접 수정은 그다음.
광학 보정이 섞인 개별 margin은 일괄 치환하지 않는다. 남기는 것은 이유를 주석으로 남긴다.
