# 패턴 — 화면이 반복하는 판단

DS1(`@ezwel/ui`)의 `patterns.md`·`principles.md`에서 **DS3에도 맞는 판단만** 옮겼다.
DS1 토큰·컴포넌트(`Ez*`) 서술은 버렸고, DS3에 이미 규칙이 있는 것은 그쪽을 가리킨다 —
화면 폭·조회 영역·표는 [`ui-conventions.md`](ui-conventions.md), 업무 상태는 [`state-rules.md`](state-rules.md),
접근성은 [`accessibility.md`](accessibility.md).

---

## 1. 목록 화면

구성: 화면 제목 → 조회 영역(`WsSearch`, UI-01) → 제목줄(건수 · 버튼) → 그리드 → 페이저(`WsPager`).

| 항목 | 규칙 |
|---|---|
| 빈 상태 | "조회 결과가 없습니다." (`QueryState`) |
| 조회 실패 | **인라인**(`QueryState`의 오류 줄). 토스트로 띄우지 않는다 — 사라지면 왜 비었는지 알 수 없다 |
| 부수 조회 실패(코드·옵션) | 반대로 토스트. 목록 자체의 실패만 화면에 남긴다 |
| 선택 행 | 배경 + 좌측 막대 둘로 — 배경색만으로는 대비가 거의 없다 |
| 조회 중 | 전체 화면 로딩을 쓰지 않는다. 표 자리 스켈레톤 — 덮으면 조회 조건을 다시 볼 수 없다 |

실제 API를 붙일 때의 골격(`src/lib`):

```ts
const { rows, loading, error, reload } = useListPage(() => fetchItems(applied.value))
const { currentPage, totalPages, paged } = usePagination(rows)   // 클라이언트 페이징일 때만
onMounted(reload)
```

`useListPage`는 늦게 도착한 앞 조회가 최신 결과를 덮지 않게 하고, 예외를 다시 던지지 않는다.
서버 페이징은 `usePagination`을 쓰지 않고 따로 설계한다(지금 목업은 `src/app/usePaged.ts`).

### 조회 영역

- 접어도 조건 값을 유지한다(`v-show`).
- 초기화는 조건만 비운다. 자동 재조회하지 않는다.
- 자동완성: 1자 이상, debounce 300ms, 그 사이 새 입력이 오면 앞 요청 취소. 공백만이면 띄우지 않는다.
  한글은 조합 중에 조회하지 않고 확정 시 한 번 거른다.

## 2. 입력 폼

| 항목 | 규칙 |
|---|---|
| 필수 | 라벨 옆 `*` + 스크린리더용 "(필수)" |
| 오류 문구 | 필드 **아래**, `role="alert"`. 색만으로 표시하지 않는다 |
| 읽기 전용 | 회색 바탕 + `readonly` (`disabled` 아님 — 복사·포커스가 된다) |
| 최대 길이 | `maxlength`로 막고 남은 글자 수를 보인다 |
| 저장 중 | 저장 버튼 비활성(`loading`) |
| 저장 실패 | 항목별 오류는 필드 아래, 그 밖은 토스트 |
| 미저장 이탈 | 확인 대화 |

서버 검증 실패를 필드에 꽂는 경로는 응답 봉투 `{success, data, error:{code, message, fields}}`의 `fields`다.

```ts
try { await save(form) } catch (e) {
  errors.value = toFieldErrors(e)
  if (!Object.keys(errors.value).length) toast(toMessage(e))
}
```

확인 대화 문구는 **무엇이 일어나는지**를 적는다 — "삭제하시겠습니까?"보다 "3건을 삭제합니다. 되돌릴 수 없습니다."

## 3. 팝업

| 상황 | 쓰는 것 |
|---|---|
| 목록을 보면서 상세 편집 | 옆 패널(Drawer) |
| 흐름을 끊어야 함(확인·경고·짧은 입력) | 모달(Dialog, `WsActionDialog`) |
| 팝업 위의 팝업 | 모달 — 패널 위에 뜰 수 있다 |

배경 클릭으로 닫지 않는다(입력이 날아간다). 겹쳐 열려도 Esc는 **가장 위 하나만** 닫는다(`useEscapeToClose`).

## 4. 상태값

상태 라벨·배지 색을 화면마다 박지 않는다. 한 곳(공통코드, 목업에서는 `src/sp/status.ts`·`src/ws/badge.ts`)에서 내려받는다.
기획이 라벨을 바꿀 때 화면을 고치게 되면 안 된다.

## 5. 일괄 등록(엑셀)

화면 구성은 UI-17. 처리 규칙:

- 지정 양식만 받는다.
- **전건 검증 후 일괄 등록.** 1건이라도 실패하면 전체 등록 불가 — 부분 저장 없음.
  어디까지 들어갔는지 사용자가 알 수 없고, 재시도하면 중복이 난다.
- 오류는 **행 단위**로("3행: 담당자 없음"). 중복은 등록하지 않는다. 실패 시 기존 데이터는 그대로.

## 6. 오류 메시지 위치

| 상황 | 위치 |
|---|---|
| 항목 검증 실패 | 필드 아래 |
| 목록 조회 실패 | 인라인 |
| 저장·삭제 실패 | 토스트 |
| 권한 없음 | 버튼을 숨기거나 비활성 |
| 세션 만료 | 모달 — 토스트는 놓친다 |

문구는 서버의 `error.message`를 그대로 쓴다. 코드별 문구 맵을 프론트가 들지 않는다.
운영자 화면만 코드를 앞에 붙인다(`toMessageWithCode`).

## 7. 판단 원칙

DS1 설계 원칙 중 값(토큰)과 무관한 것.

**공리** — ① 값은 스케일에서만 고른다(임의 px 금지, `--ws-gap-*`). ② 여백은 넉넉히 시작해 줄인다.
③ 흑백으로 위계를 먼저 세운다. ④ 관계는 거리로 말한다 — 여백으로 갈리는데 선까지 그으면 두 번 말하는 것.
⑤ 브라우저와 싸우지 않는다 — 고정 폭보다 `flex-wrap`·`auto-fit`(`.ws-cluster`·`.ws-grid`).

**조작**

| 원칙 | 규칙 |
|---|---|
| 상태 가시성 | 400ms를 넘으면 사용자는 "멈췄나" 생각한다 — 로딩을 그린다 |
| 되돌릴 길 | 파괴적 동작 앞에 확인 |
| 오류 예방 | 못 누르게 하는 것이 누른 뒤 막는 것보다 낫다 |
| 인식 > 회상 | 코드 대신 라벨 |
| 관례 | 조회는 위, 목록은 아래, 저장은 오른쪽 |
| Fitts | 삭제를 저장 옆에 붙이지 않는다 |
| Hick | 선택지 3개 넘으면 셀렉트, 10개 넘으면 검색 |
| Von Restorff | 영역마다 주 버튼 하나 |

**공개 클래스 이름은 API다.** `src/ws`가 내놓는 `ws-*` 이름은 화면의 전역 공간을 차지한다.
화면은 그 이름을 다시 정의하지 않고(`check:ui` UI-30), 구체적인 것에는 한정어를 붙인다(목록 그리드는 `.ws-gv`, `.ws-grid`가 아니다).
배경은 [`lessons-from-audits.md`](lessons-from-audits.md).

**리뷰에서 묻는 다섯** — 이 여백은 어느 역할 토큰인가 · 그룹 사이가 그룹 안의 두 배인가 ·
흑백으로도 위계가 서는가 · 이 화면의 주 버튼은 무엇인가(하나인가) · 빈·오류·로딩을 그렸는가.
