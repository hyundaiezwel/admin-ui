# EZ Admin Design System 2

사내 관리자센터(WebSquare 5 BO-UI)의 퍼블리싱을 **정본**으로 삼은 어드민 디자인 시스템과 목업.

[DS1(`ez-admin-design-system`)](https://github.com/hyundaiezwel/ez-admin-design-system)과 **같은 화면 열 장**을 다른 어휘로 짰다.
DS1이 "앞으로 어떤 톤으로 갈까"라면, DS2는 "지금 쓰는 화면을 그대로 두고 부품만 바꾸면 어떻게 되나"다.

```bash
npm install
npm run dev     # http://localhost:5310
npm run build   # 대비 검사 → 타입 검사 → 빌드
```

## 정본

값은 전부 [`ez-websquare-vue`](https://github.com/hyundaiezwel/ez-websquare-vue)의 원본 `cm/css/contents.css`·`base.css`에서
실측하거나 빈도로 뽑았다. 원본 CSS에는 커스텀 프로퍼티가 0개라 `src/ws/tokens.css`가 그 하드코딩 값에 이름을 붙인 층이다.

| | 값 | 원본 |
|---|---|---|
| 컨트롤 높이 | 32px | `.w2input` · `.btn_cm` |
| 그리드 헤더 · 행 | 34 · 35px | `.gridHeaderTDDefault` · `.gridBodyDefault` |
| 입력 표 행 · 조회 표 행 | 44 · 40px | `.tb .w2tb_th` · `.shbox .tb .w2tb_th` |
| 모서리 | 6px | 최빈 27회 |
| 글자 | 14px 한 벌 | `1.4rem` (html 62.5%) |
| 화면 안쪽 | 30 48 24 | `.sub_contents` |
| 블록 사이 | 24px | 인접 형제 규칙 48개 중 27개 |
| 제목 영역 아래 | 18px | `.pgtbox{margin:0 0 18px}` |
| 제목줄 → 내용 | 12px | `.titbox{margin-bottom:12px}` |

**주버튼이 둘이다.** 원본 규칙 그대로 옮겼다.

| | 색 | 쓰는 곳 |
|---|---|---|
| `.ws-btn--pri` | 진회색 `#444` | 저장·등록 — 원본 `.btn_cm.pri` |
| `.ws-btn--search` | 초록 | 조회 · 팝업 확인에만 — 원본 `.shbox .btn_cm.pri` |

## 원본에서 고친 값 — 8건

"모양 유지, 값만 고침"(2026-09-28 결정). **같은 색상·채도에서 명도만** 최소로 내려 기준을 넘겼다.
산출은 `scripts/fix-contrast.mjs`, 검증은 `npm run check:contrast`(빌드에 물려 있다).

| 자리 | 원본 | 대비 | 교정 | 대비 |
|---|---|---|---|---|
| 조회·팝업 확인 버튼 (흰 글자) | `#009782` | 3.65 | `#008472` | 4.62 |
| 보조 버튼 (흰 글자) | `#aaaaaa` | 2.32 | `#757575` | 4.61 |
| 입력 테두리 | `#cccccc` | 1.61 | `#939393` | 3.07 |
| 브랜드 글자 | `#009782` | 3.34 | `#007d6c` | 4.63 |
| 위험 글자 · 필수 `*` | `#f04452` | 3.40 | `#dc1222` | 4.62 |
| 성공 글자 | `#00af7a` | 2.59 | `#007f59` | 4.59 |
| 링크 | `#1573e1` | 4.20 | `#146dd5` | 4.60 |
| 설명 글자 | `#727272` | 4.40 | `#6f6f6f` | 4.59 |

**글자의 기준면은 흰색이 아니라 머리 면 `#f3f5f6`이다.** 폼 라벨 칸과 그리드 헤더가 이 색이고,
원본에 `th.gridHeaderTDDefault.txt_red` 같은 규칙이 있어 색 글자가 실제로 여기 올라간다.
처음에 흰색으로 잡았다가 다섯 건이 머리 면에서 다시 미달로 나왔다 — 링크와 설명 글자는 흰 바탕에서는 통과한다.

**표·그리드의 `#ccc` 선은 고치지 않았다.** 장식선이라 WCAG 1.4.11 대상이 아니다 — 셀 배경과 정렬이 구분을 맡는다.
입력 테두리만 컨트롤 경계를 알리는 **유일한** 선이라 3:1이 필요하다. 그래서 테두리를 둘로 갈랐다(`--ws-border` / `--ws-field-border`).

고칠 필요가 없는데 고칠 뻔한 것도 둘 있었다. 셸 레일 아이콘 색 `#9aa8a5`(4.49)는 글자 기준으로는 미달이지만
레일에 아이콘만 있어 비텍스트 3:1 기준이 맞고 통과한다. 메뉴 검색 안내 글자 `#aaa`도 5.14로 통과한다. 둘 다 원본 그대로 둔다.

## 구조

```
src/ws/           디자인 시스템 층
  tokens.css        값 — 원본 실측 + 교정 8건
  base.css          전역 — 글꼴·포커스 링
  layout.css        화면 블록 — page · pgt · sh · sec/tit · tb · gtb · btnbox · msg
  controls.css      네이티브 요소에 입히는 클래스 — 버튼 · 입력 · 선택 · 체크 · 뱃지
  WsDialog.vue      팝업 · 옆 패널 — 네이티브 <dialog>
  WsTabs.vue        탭 — WAI-ARIA 탭 패턴
  WsCheckCombo.vue  다중 선택 — <details> + 체크박스
  WsSearch.vue      조회 영역 — 목록 화면 다섯 장이 같이 쓴다
src/grid/         Tabulator 래퍼 + WebSquare 스킨
src/app/          셸 조각 · 차트 래퍼 · 조회 상태
src/pages/        화면 열 장 (DS1과 같은 목록)
```

### 원칙 넷

**① 네이티브 먼저.** 원본도 대부분 네이티브다(`xf:select1` → `select`). 컴포넌트는 동작이 있는 넷뿐이다.

| 필요 | 쓴 것 | 공짜로 얻는 것 |
|---|---|---|
| 팝업 · 옆 패널 | `<dialog>` | 포커스 가두기 · Esc · 배경 차단 |
| 날짜 | `<input type="date">` | 키보드 · 모바일 |
| 자동완성 | `<input list>` + `<datalist>` | 한글 IME 조합 |
| 다중 선택 | `<details>` + 체크박스 | 펼침 상태 읽어 주기 |

**② 간격은 한 규칙으로.** 원본은 인접 형제 선택자 48개로 간격을 준다. 조합에 없는 순서는 간격이 0이 된다.
값을 뽑으면 거의 전부 24라서 `.ws-page > * + *` 하나로 접고, 다른 값은 제목 영역(18) 하나만 따로 뒀다.

**③ 편집 상자는 고칠 수 있는 칸에만.** 원본 그리드는 `:not(.w2grid_default_readonly)`로 편집 셀에만 안쪽 상자를 그린다.
상자는 "여기 고칠 수 있다"는 신호라 읽기 전용 칸에 주면 거짓말이다. 상태로 잠긴 행(진행 중 프로모션)도 상자를 거둔다.

**④ 50행 이하 조회 전용은 정적 표.** Tabulator를 띄울 이유가 없다. `.ws-gtb`가 그리드와 같은 치수라 섞여도 한 화면으로 읽힌다.

### 새 화면 만드는 순서

1. 루트는 `.ws-page`, 첫 자식은 `<PageHead />` — 제목·경로는 메뉴 트리에서 나온다
2. 목록이면 `<WsSearch>`에 `<tr>`만 넘긴다 — 라벨·칸 세 쌍이 한 줄
3. 구획은 `.ws-sec` = `.ws-tit`(왼쪽 제목·건수 / 오른쪽 버튼) + 내용
4. 조회는 초록, 저장은 진회색. 윤곽 알약(`--line`)은 그리드 제목줄의 보조 동작
5. 목록은 `<QueryState>`로 감싼다 — 로딩 · 오류 · 빈 · 정상
6. 입력 표는 `.ws-tb`, 필수는 `th.req`

## 실측으로 잡은 것

**그리드 행이 35가 아니라 41·37·36으로 나왔다.** 원인이 셋 겹쳐 있었다.

1. 칸마다 `min-height: 35px` — 선 1px이 그 위에 얹혀 36
2. 체크박스 기본 `margin: 3px` + 기준선 정렬 — 그 칸만 36이 되고, **Tabulator가 그 높이를 전 칸에 인라인 `height`로 복사**
3. 24px 뱃지가 기준선에 붙어 34.5 — 반올림되면 36

세 개 다 고쳐야 35가 나온다. 하나씩 고칠 때마다 1~2px씩 줄었다. 전부 `tabulator-ws.css` 주석에 남겼다.

9화면 전수 실측 — 블록 간격 `[18, 24]`, 그리드 행 `35`, 콘솔 오류 0.

## DS1과 공유하는 것

| | DS1 | DS2 |
|---|---|---|
| 그리드 | Tabulator + `pasteGuard` · `rowSelect` | 같은 래퍼, 스킨만 다르다 |
| 차트 | ECharts 래퍼 | 같다. 팔레트도 같은 참조 팔레트 |
| 조회 상태 | `useMockQuery` · `QueryState` | 같은 원리, 모양만 다르다 |
| 탭 폭 | 180px 고정 | 같다 |
| UI 라이브러리 | PrimeVue 4 | **없다** — 네이티브 + 클래스 |
| 토큰 | `@ezwel/ui` | `src/ws/tokens.css` — 원본 값 |
| 다크 모드 | 있다 | **없다** — 원본에 없다. 만들면 발명이다 |

## 감수한 것

- **차트 선 셋 이상 라이트 화면** — 참조 팔레트의 주황·초록·하늘이 흰 바탕 3:1 미달이다. `check:contrast`가 경고로 찍는다(DS1 v1.6.1과 같은 결정).
- **차트 패턴 없음** — 적록 색각이상 여유가 없다. 범례를 빼면 안 된다.
- **간격 부등식** — 원본도 지킨다. 구획 사이 24 ≥ 구획 안(제목줄 → 내용) 12 × 2. 처음에 이 자리를 `--ws-gap-inter` 12와 `--ws-gap-intra` 8로 비교해 "안 지킨다"고 적었는데, 둘은 같은 자리의 간격이 아니었다(8은 폼 칸 **안**의 제목 → 내용).
